# Etapa 5b — aguenta o público: plano de implementação

> **Para quem executa com agentes:** SUB-SKILL OBRIGATÓRIA — use
> `superpowers:subagent-driven-development` (recomendado) ou
> `superpowers:executing-plans` para executar tarefa a tarefa. Os passos usam
> caixas (`- [ ]`) para acompanhamento.

**Objetivo:** tirar do processo do site o trabalho que pode derrubá-lo, e fixar
o teto de entidades num número medido em vez de suposto.

**Arquitetura:** a exportação passa a funcionar como a extração já funciona — o
`POST` enfileira e devolve na hora, o trabalho roda em processo separado com
teto de memória e de CPU, e a tela consulta o estado até ficar pronto. **A mesma
fila serve os dois tipos de trabalho**, e o cache continua respondendo na hora,
sem enfileirar e sem consumir cota.

**Pilha:** Python 3.13, FastAPI, `ProcessPoolExecutor`, SQLite, TypeScript.

**Desenho que governa:** `docs/superpowers/specs/2026-08-28-deploy-design.md`,
seção "Bloco 5b". Leia antes de começar.

> **O bloco 5a precisa estar no ar antes da Tarefa 4.** As tarefas 1 a 3 são
> código de aplicação e rodam em qualquer máquina; a 4 é medição, e medir num
> laptop Windows um teto que vale para uma VPS Linux não mede nada.

## Restrições globais

Valem para **todas** as tarefas; cada tarefa herda esta seção inteira.

- **Nenhuma dependência nova.** `requirements.txt`, `web/requirements.txt` e
  `web/frontend/package.json` terminam a etapa com exatamente as linhas que já
  têm.
- **Sem pytest.** Testes são funções com `assert` e um bloco
  `if __name__ == "__main__":` que as chama e imprime `OK: ...`. Rodam com
  `./.venv/Scripts/python.exe tests/test_x.py`. Nunca use `python` puro.
- **Um processo uvicorn.** As cotas supõem isso.
- **A ordem é lei: chave, arquivo, e só então cota.** Está comentada em
  `web/api/main.py:405-408` e é o que permite reexportar uma combinação já
  gerada mesmo sem vaga. **Nenhuma tarefa pode inverter essa ordem** — há teste
  que a afirma (`test_download_esgotado_responde_429`).
- **A cota é reservada no pedido, não na entrega.** Senão dez pedidos
  enfileirados passam todos pela conferência antes de qualquer um consumir.
- **Texto de tela por `textContent`**, nunca `innerHTML`.
- **Toda mensagem de erro diz o que houve e o que fazer.**
- **Commit ao fim de cada tarefa**, em português, **sem acentos no assunto**.

  - `storage.atualizar_ficha(job_id: str, mudar: Callable[[dict], None]) -> bool`
  - `jobs.aplicar_limites(memoria: int, cpu: int) -> str` (era `_aplicar_limites`)
  - `exportacao.estado(job_id: str, ch: str) -> dict | None`
  - `exportacao.pedir_exportacao(job_id, pagina, escala, unidade, opcoes,
    referencia) -> dict` — **sempre com a chave `"novo"`**: `True` quando este
    pedido enfileirou, `False` quando devolveu um estado que já existia. A
    Tarefa 2 depende disso para não deixar reserva de cota pendurada.
  - `limits.TRABALHOS_SIMULTANEOS` (era `EXTRACOES_SIMULTANEAS`)

> **Uma fila só, e é decisão consciente.** Duas filas de 4 trabalhadores a 6 GB
> cada dariam 48 GB de teto numa VPS de 16 GB — o dobro do que existe, duas
> vezes. Compartilhar limita o trabalho pesado total, que é o que importa. O
> preço é que uma exportação longa pode atrasar uma extração; com 4 lugares e a
> cota limitando quantas exportações acontecem, é preço justo. Se um dia
> apertar, a saída é fila com prioridade, não fila separada.

> **A trava da ficha é a armadilha desta tarefa.** Hoje só `jobs._gravar_estado`
> reescreve a ficha, sob a `_trava` dele. Se a exportação ganhar uma trava
> própria, as duas passam a reescrever **o mesmo arquivo** sob travas
> diferentes: extração e exportação terminando juntas leem a mesma ficha, e a
> última a gravar apaga o estado da outra. É atualização perdida clássica, e o
> sintoma seria uma página voltando de `"pronta"` para nada, sem ninguém
> entender por quê. Por isso a mutação vai para `storage`, com **uma trava só**.

```python
# A ficha é um arquivo só, reescrito inteiro. Extração e exportação gravam
# estados diferentes dentro dela, e sem uma trava **comum** as duas leem a
# mesma versão e a última a gravar apaga o trabalho da outra. A trava mora
# aqui, e não em quem chama, porque é do arquivo que ela protege.
_trava_de_ficha = threading.RLock()


def atualizar_ficha(job_id: str, mudar) -> bool:
    """Lê, aplica `mudar(ficha)` e grava, sob a trava do arquivo.

    Devolve `False` quando não havia ficha — trabalho expirado, apagado pela
    cota, ou envio desfeito. **Não recria:** um toco sem `n_paginas` nem `nome`
    seria pior que a ausência, porque as rotas o tratariam como trabalho.
    """
    with _trava_de_ficha:
        ficha = ler_ficha(job_id)
        if ficha is None:
            return False
        mudar(ficha)
        gravar_ficha(job_id, ficha)
        return True
```

`gravar_ficha` no nome do temporário.

```python
_trava = threading.RLock()


def estado(job_id: str, ch: str) -> dict | None:
    """O estado desta exportação, ou `None` se ninguém a pediu."""
    ficha = storage.ler_ficha(job_id)
    if ficha is None:
        return None
    return ficha.get("exportacoes", {}).get(ch)


def _gravar_estado(job_id: str, ch: str, novo: dict) -> None:
    storage.atualizar_ficha(
        job_id, lambda f: f.setdefault("exportacoes", {}).__setitem__(ch, novo))


def _exportar_no_worker(job_id: str, pagina: int, escala: float, unidade: str,
                        opcoes: dict, memoria: int, cpu: int) -> dict:
    """Roda **no processo filho**. Os tetos chegam por argumento.

    O processo pai continua sendo o único dono da política — é o mesmo desenho
    de `jobs._extrair_no_worker`, e a razão é a mesma: o filho não deve poder
    escolher os próprios limites.
    """
    aplicados = jobs.aplicar_limites(memoria, cpu)
    entidades = _gerar_de_fato(job_id, pagina, escala, unidade, opcoes)
    return {"situacao": "pronta", "entidades": entidades,
            "limites_aplicados": aplicados}


def _quando_terminar(job_id: str, ch: str, referencia: str, futuro) -> None:
    """Grava o desfecho e acerta a cota. **Nunca levanta.**

    `concurrent.futures` engole exceção de callback em silêncio: sem a rede de
    segurança do `except` de baixo, uma falha aqui deixaria a exportação presa
    em `"na_fila"` para sempre, e o navegador consultando até desistir.
    """
    try:
        try:
            resultado = futuro.result()
        except (BrokenProcessPool, MemoryError):
            resultado = {"situacao": "erro", "codigo": "recurso",
                         "mensagem": "Não consegui gerar este DXF: ele passou "
                                     "do limite de memória ou de tempo do "
                                     "servidor. Tente com mais compactação, ou "
                                     "com menos camadas."}
        except Exception:
            traceback.print_exc()
            resultado = {"situacao": "erro", "codigo": "interno",
                         "mensagem": "Não consegui gerar este DXF. A falha foi "
                                     "registrada no servidor. Tente de novo em "
                                     "instantes."}
        _gravar_estado(job_id, ch, resultado)
        if resultado["situacao"] == "pronta":
            quotas.confirmar(referencia)
        else:
            # O usuário não levou DXF nenhum, e não paga por isso.
            quotas.soltar(referencia)
    except Exception:
        traceback.print_exc()
        with contextlib.suppress(Exception):
            _gravar_estado(job_id, ch, {
                "situacao": "erro", "codigo": "interno",
                "mensagem": "Não consegui gerar este DXF. A falha foi "
                            "registrada no servidor. Tente de novo em instantes."})


def pedir_exportacao(job_id: str, pagina: int, escala: float, unidade: str,
                     opcoes: dict, referencia: str) -> dict:
    """Enfileira, ou devolve o estado que já existe. **Não confere cota.**

    Quem confere é a rota, antes de chamar — e só quando o arquivo ainda não
    existe. A ordem "chave, arquivo, cota" é lei do projeto.

    Conferir e submeter acontecem sob a mesma trava porque as rotas do FastAPI
    são síncronas e rodam num pool de threads: dois pedidos idênticos chegando
    juntos passariam os dois pela conferência antes de qualquer um gravar, e
    dois workers gerariam o mesmo desenho.

    **`"novo"` diz se este pedido foi o que enfileirou.** Quem chama precisa
    saber: a reserva de cota de um pedido que só encontrou trabalho alheio em
    andamento não tem quem a confirme nem quem a solte — o callback é do
    primeiro pedido —, e ficaria pendurada para sempre.
    """
    ch = chave(pagina, escala, unidade, opcoes)
    with _trava:
        atual = estado(job_id, ch)
        if atual and atual.get("situacao") in ("na_fila", "pronta"):
            return {**atual, "novo": False}
        _gravar_estado(job_id, ch, {"situacao": "na_fila"})
        try:
            futuro = jobs.pool().submit(
                _exportar_no_worker, job_id, pagina, escala, unidade, opcoes,
                limits.TETO_MEMORIA_WORKER_BYTES, limits.TETO_CPU_WORKER_SEGUNDOS)
        except Exception:
            traceback.print_exc()
            erro = {"situacao": "erro", "codigo": "interno",
                    "mensagem": "Não consegui pôr este DXF na fila. Tente de "
                                "novo em instantes."}
            _gravar_estado(job_id, ch, erro)
            return {**erro, "novo": True}
        futuro.add_done_callback(
            lambda f: _quando_terminar(job_id, ch, referencia, f))
        return {"situacao": "na_fila", "novo": True}
```

```python
def exportar_e_esperar(job: str, pagina: int, corpo: dict,
                       limite_s: float = 60.0) -> dict:
    """Exporta e espera terminar, devolvendo o estado final.

    Espera a **condição**, nunca um tempo de relógio: numa máquina ocupada a
    exportação demora mais, e dormir um tanto arbitrário troca um falso
    vermelho por outro.
    """
    r = cliente.post(f"/api/jobs/{job}/pages/{pagina}/export", json=corpo)
    assert r.status_code == 200, (r.status_code, r.text)
    inicial = r.json()
    if inicial["situacao"] == "pronta":
        return inicial
    ch = inicial["chave"]
    fim = time.time() + limite_s
    while time.time() < fim:
        e = cliente.get(f"/api/jobs/{job}/pages/{pagina}/export/{ch}")
        assert e.status_code == 200, (e.status_code, e.text)
        atual = e.json()
        if atual["situacao"] in ("pronta", "erro"):
            return atual
        time.sleep(0.05)
    raise AssertionError(f"a exportação não terminou em {limite_s}s")
```

> **O caminho sutil, e é por isso que `"novo"` existe.** A tentação é soltar a
> cota quando `pedir_exportacao` devolve um estado que já existia — "esta
> chamada não enfileirou nada, então não deve cobrar". **É armadilha:** a
> `referencia` é a mesma (`job_id:ch`), e `soltar` marcaria como `solto` a
> linha do **primeiro** pedido, que ainda está `reservado`. O worker
> terminaria, `confirmar` não acharia nada, e bastaria clicar duas vezes para
> exportar de graça.
>
> O certo é não fazer nada: a segunda `reservar` é idempotente por
> `(referencia, tipo, balde)` e não cria linha nova, então existe **uma reserva
> só**, e quem a acerta é o callback do primeiro pedido. O `"novo"` serve para
> distinguir isso do caso de erro, onde soltar é obrigatório.

> **Limitação conhecida, e não vale complicar por ela:** dois usuários
> diferentes pedindo a mesma chave do mesmo trabalho ao mesmo tempo teriam
> baldes diferentes e linhas diferentes, e `confirmar(referencia)` acertaria as
> duas. Exige o mesmo `job_id`, que é por envio — na prática não acontece.
> Registre, não construa contra.

```typescript
export type EstadoExportacao = {
  situacao: "na_fila" | "pronta" | "erro";
  chave: string;
  url?: string;
  cache?: boolean;
  entidades?: number;
  codigo?: string;
  mensagem?: string;
};

/**
 * Espera o DXF ficar pronto, com o mesmo recuo da espera da extração.
 *
 * Uma planta pesada leva minutos, e bater a cada 300 ms por minutos é ruído à
 * toa; um intervalo fixo longo faria a planta leve parecer lenta. Por isso o
 * intervalo dobra até saturar — é a mesma razão de `esperarPagina`, e as duas
 * usam as mesmas constantes de propósito.
 */
export async function esperarExportacao(
  job: string, pagina: number, ch: string, sinal: AbortSignal,
  aoMudar: (e: EstadoExportacao) => void,
): Promise<EstadoExportacao> {
  let espera = ESPERA_INICIAL;
  let anterior = "";
  for (;;) {
    if (sinal.aborted) throw new DOMException("Aborted", "AbortError");
    const r = await pedir(
      `/api/jobs/${job}/pages/${pagina}/export/${encodeURIComponent(ch)}`,
      { signal: sinal });
    const estado = await r.json() as EstadoExportacao;
    if (estado.situacao !== anterior) {
      anterior = estado.situacao;
      aoMudar(estado);
    }
    if (estado.situacao === "pronta" || estado.situacao === "erro") return estado;
    await dormir(espera, sinal);
    espera = Math.min(espera * 2, ESPERA_MAXIMA);
  }
}
```
